# ADR-005 · Agente acotado (≤2 llamadas LLM) + búsqueda web en el MVP

- **Estado:** Aceptado
- **Issue vinculada:** #17 — Pipeline de Consulta RAG con Citas · #8 — tool `web_search`
- **Fecha:** 2026-09-30
- **Decisor:** TL (rodrigoasis87)

> Formaliza la "Actualización (2026-09-30)" del ADR-001: el **MVP incluye
> agente + búsqueda web**, no queda para post-MVP.

## 1. Contexto

El enunciado pide "Insurance Policy Generation Chatbot" con agentes y tools de
LangChain. El MVP responde sobre las pólizas del corpus (RAG) y, cuando el
corpus no alcanza pero la pregunta es del rubro (precios/benchmarks de mercado),
debía buscar en internet. El trade-off: un agente libre (ReAct abierto) puede
encadenar llamadas y web crawls lentos en CPU-only (ADR-001).

## 2. Decisión

- `query(question, top_k=5)` es un **agente acotado a ≤2 llamadas LLM** por
  consulta:
  1. `search()` + hard gate `UMBRAL_SCORE` (ADR-004) → contexto filtrado.
  2. **1.ª llamada LLM**: respuesta *grounded* con citas (`poliza · Art. N`);
     si el contexto no alcanza y la pregunta es del rubro (`guardrail` de
     dominio en el prompt) → **2.ª llamada con `web_search`**; si no es del
     dominio → negativa con alcance.
- `web_search` usa **DuckDuckGo** (`ddgs`, sin API key), la **única pieza con
  internet** (ADR-001). Máximo **1 búsqueda web por consulta**.
- Las fuentes de web se marcan siempre (`origen: web`, con `url`) y se
  diferencian de las de póliza (`origen: poliza`) en la UI (#18).

## 3. Alternativas evaluadas

| Opción | Por qué se descartó |
|---|---|
| Agente ReAct de llamadas ilimitadas | Latencia y drift en CPU-only; rompe el presupuesto de demo (≈5–15 s) |
| Sin web en el MVP | No cubre el deliverable de "noticias/precios" y el caso "contexto insuficiente" |
| `web_search` como llamada de Tool dentro de la misma invocación | Contradice el juicio del contexto (retrieve → ¿responde? → buscar); el guardrail entre llamadas es el punto de control |

## 4. Consecuencias

- Presupuesto determinístico de latencia: ≤2 llamadas LLM + ≤1 búsqueda web.
- El `UMBRAL_SCORE` (ADR-004) es el *primer* filtro; el guardrail de dominio el
  *segundo*; post-MVP los reemplaza el clasificador de intención (ARCHITECTURE
  §3) sin reescribir `query()`.
- `#17` consume `search()` (ADR-004) y el tool `web_search` (#8).
- Aceptado: `ddgs` puede degradarse sin key; el tool falla controlado y `query()`
  responde solo con corpus o niega con alcance.
